# 2026-11-18 全量审查修复记录

## 范围与边界

按此前审查的 12 项顺序修复，不新增依赖、请求拦截、负向缓存或对话留存；不截断已加载日志，不改变既有全局加密状态恢复策略。本轮工作保留此前未提交修改，没有提交、push 或切换现有服务。

| 项目 | 修复与保持的合同 |
| --- | --- |
| 配置加载/恢复 | 复用完整导入的容器类型检查；拒绝错误类型而非静默丢档案。合法省略、legacy 与局部 PATCH 保持兼容，失败恢复不改当前配置。 |
| 健康详情导航 | 普通点击走应用内导航，保留未保存草稿；修饰键仍走原生链接。 |
| 主题存储失败 | 只隔离可选偏好写入并记录警告；主题、meta 和系统监听仍生效。 |
| SSE 工具终态 | 拒绝与截断优先于工具终态，包括最终 output 未列出已流出工具的情况。 |
| JSON 自定义工具 | `custom_tool_call` 与 `function_call` 一样返回 `tool_use`，不覆盖 refusal/max_tokens。 |
| 凭据身份 | 共享无碰撞编码贯穿 Primary/Claude 健康、亲和及默认 state domain；区分 candidate ID、raw profile ID 和实际 key ID。 |
| OAuth 过期边界 | 校验最终 Date，而非只检查秒数；无效过期值不写坏账户，刷新失败保留旧凭据和既有诊断。 |
| 抓包正文失败 | HTTP 200 的读取/解析失败明确拒绝并可重试，不伪装成功；非成功 HTTP 的既有生命周期语义不变。 |
| 健康等待期限 | curl 的连接/传输期限使用剩余总预算；禁止零预算启动 curl，耗尽后返回失败。 |
| DST 范围身份 | 相对范围名称随成功统计快照原子提交；不再从毫秒长度推断，新范围加载期间仍准确标识旧数据。 |
| SQL 重复工作 | 搜索/下钻只匹配一次供 facets 使用；同范围统计共用投影/汇总。快照、筛选排除自身维度、未知 route 计数及 worker 维护协调保持。 |
| 日志重复渲染工作 | 未变化组先做引用比较，保留结构比较兜底；移动卡片共享父层媒体偏好。历史 DOM、检索文本、焦点、展开与滚动合同不变。 |

身份编码只改变包含 `%`、`#`、`:` 或 UTF-16 surrogate 的内部身份/默认域，公开 ID 不变，普通 ID 保持旧格式；不提供有碰撞的旧键兼容回退。显式声明的 `state_domain_id` 和 OAuth 域优先级不变。显式 Codex 档案仍不参与共享自动调度/健康结算，其目标域对应实际发送的密钥。

## 性能对照

同一 100,000 条合成日志 SQLite、同机三轮中位数，比较此前审查基线与本轮隔离构建。每种查询的完整输出（忽略 `generated_at`）签名相同；不是生产负载承诺。

| 查询 | 修复前 | 修复后 | 相关 SQL 数量前 → 后 |
| --- | ---: | ---: | ---: |
| 普通分页 | 1.23 ms | 1.31 ms | 0 → 0（facets 快路径） |
| 命中文本搜索 | 209.72 ms | 88.51 ms | 5 → 2 |
| 无结果文本搜索 | 305.74 ms | 116.70 ms | 5 → 2 |
| usage 统计 | 551.63 ms | 273.88 ms | 4 → 1 |
| full 统计 | 1289.51 ms | 652.20 ms | 11 → 5 |

相关 SQL 数量只计包含 `LIKE` 或 `analytics_rows` 的准备语句，不代表全部查询数或实际物理扫描计划。`AS MATERIALIZED` 只在单次查询内共用中间结果，SQLite 可使用内存或临时磁盘；不是第二份持久业务数据、跨请求缓存或新增数据库 Schema。普通分页差异处于该次测量噪声范围。仍保留现有分位数和 overview 查询，没有为优化增加搜索结果限制。机制参考 [SQLite WITH materialization hints](https://www.sqlite.org/lang_with.html#materialization_hints)。

2000 行、32 组的未变化日志比较器合成基准，每次比较成本约 5.09 → 0.013 ms；这是比较器成本，不是页面整体延迟。200 个移动卡片自身新增媒体订阅从 200 降为 0，偏好由父层共享。

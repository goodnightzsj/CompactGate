# Studio 页面加载性能

## 已确认的慢路径

- 页面模块按需下载。现有进程曾出现静态 GET 6–15 秒没有首字节，而 HEAD、部分 API 正常；同一文件在独立进程约 3ms 返回。这能定位到原进程的资源交付路径，尚不能证明其具体内部等待点。
- 仪表盘与用量离页后卸载，原先只保留选择条件，返回时丢失统计数据并重新查询。
- 统计使用同步 SQLite，在 HTTP 主线程连续执行多条查询；全库累计和分位数开销会影响其他 API、SSE 与代理请求。
- 用量原先连带计算不用的路由、Host、模型路径与分位数；健康查询最近 compact 记录缺少匹配的索引。
- 配置与健康接口原先通过 `Promise.all` 一起提交，较慢的一侧延迟另一侧的展示。

## 实现与合同

静态文件由一个 `ReadStream` 负责打开和关闭，不再同时交给 `FileHandle` 与流管理。等待首次可读后才设置成功响应及 immutable 缓存头。首次打开/读取超时为 5 秒，返回 `503` 和 `Cache-Control: no-store`；打开/首次读取错误保持 HTTP 失败，传输途中错误中断响应。HEAD 不读取正文；客户端离开即取消等待或传输。错误监听保留到流实际关闭，取消或超时后迟到的文件打开错误记录诊断，不再作为未处理事件退出进程。这是有界故障处理，不代表已证明原生产进程卡住的原因，也不保证异常磁盘 I/O 一定成功。

`request_logs` 新增幂等索引 `(route, id DESC)`，服务下一次正常启动时创建。保留时间范围改为两个独立的 `MIN(time)` / `MAX(time)` 索引查询。原有 Token、错误分类、分位数、Top N 和保留记录口径不变。

每个 `RequestLogger` 在首次 HTTP 统计请求时启动一个只读 worker；所有统计 SQL 在一个读事务中执行。写入和清理提交后，下次请求读取新数据；不增加服务端结果缓存、汇总表或历史正文留存。同步 `logger.stats()` 仍供现有内部调用使用，HTTP 使用 `statsAsync()`。

包含正在执行的查询，最多允许 8 个在途统计任务；超过返回 `503` 与 `Retry-After: 1`。排队请求取消即移除，正在执行的请求取消后丢弃结果，但仍占用执行槽直到结束。每个执行任务有 60 秒期限，超时明确失败并请求终止 worker；Node 22 无 SQLite interrupt API，当前原生 SQL 可能需要执行完才释放线程。终止期间不另开线程。关闭服务等待 worker 清理。长读事务可能延迟 WAL 回收，首次全库统计仍随数据量增长。

手动正文清理和自动回收的每个同步阶段，由统计 reader 在当前真实读事务结束后执行，再启动下一条统计；调用方取消不提前释放这个边界。`purgeStoredBodies()` 返回 Promise，HTTP 等待清理结束再响应。已创建 reader 的非 deferred logger 也采用异步调度；未创建 reader 时保留原有同步自动回收。维护失败与关闭明确拒绝等待任务，外部读者引起的 busy 错误仍保留。单次 UPDATE/VACUUM 仍同步执行，不保证磁盘回收期间零阻塞。

`GET /api/logs/stats` 的默认完整结构不变，包括原有 `range.includeOverview`。新增 `view=usage`，返回 `view: "usage"`，保留范围、趋势、模型、端点和用量摘要，省略 `by_route`、`by_host`、`model_mappings` 以及摘要内四个分位数字段，`overview` 为 `null`。未知 view 或 `view=usage&overview=1` 返回 `400`，仅作用于 stats；recent 下钻只复用时间范围校验，不校验统计专属参数。普通 SQL/worker 失败保持明确的 `500`，不回退主线程或伪造空结果。

前端仅为仪表盘、用量各保留一份最近成功快照，生命周期属于当前 Studio，不写入磁盘或浏览器存储。查询范围/预设、overview 与 view 必须匹配；60 秒内复用，过期先展示后刷新，强制刷新绕过复用。离页取消请求并停止轮询，旧响应不能覆盖新选择，失败保留上次成功数据与错误。标签页隐藏取消请求，重新可见立即刷新。配置和健康独立提交，各自失败仍可见；SSE 或轮询确认恢复后，旧请求迟到的成功或失败均不会重新显示旧错误。草稿与 revision 保护保持原合同。

bootstrap 请求携带发出时的配置基线，现有配置 reducer 仅在基线未被替换时接受响应；SSE、导入、保存、档案切换已经更新配置后，迟到响应不会覆盖新配置及 formRevision。健康响应也通过状态更新函数比较请求起点，保留期间收到的新健康信息。两侧分别判定，不互相取消；正常重试能接收新结果，表单独立编辑仍沿用原有草稿冲突规则，不解析配置 revision 或新增数据缓存。

错误横幅由同一 reducer 的内存 `pageErrorRevision` 管理归属。SSE/轮询恢复、显式页面错误更新会增加版本；bootstrap 成功或失败仅在版本仍匹配时提交错误状态。新操作错误不会继承旧 bootstrap 的失败标记，因而也不会被后续恢复事件清除。版本只控制横幅，不拦截两侧数据加载；重试捕获新版本，真实失败仍明确显示。

## 验证

全部构建和运行验证使用隔离目录、合成数据与新端口，不覆盖现有 `dist/`、不复制生产凭据、不切换现有服务。

回归修复额外覆盖：真实 ReadStream 在取消/超时后迟到 open 错误（修复前两个子进程均崩溃）；统计取消后维护仍等待真实事务、自动回收、等待期间关闭、执行超时与外部读锁失败重试；SSE/轮询 × config/health 四种恢复时序；完整统计和 recent 参数兼容。百万行合成复核中，统计与清理并发总计约 10.4 秒后成功，清除 1 条正文并保留全部 100 万条元数据，等待期间 10ms 定时器执行 826 次；这不是单次 VACUUM 无阻塞或生产尾延迟保证。

后续配置时序复核新增 6 个先失败的用例：SSE/导入/保存/档案更新后迟到配置响应、同批次 SSE 与旧重试结束时的脏草稿/固定 revision，以及配置请求失败后迟到健康响应。修复后正常重试和两侧独立加载仍通过；相关配置、OAuth、优先级与生命周期测试合计 104 项通过。

错误归属复核再补 9 个先失败的用例，覆盖两侧迟到失败、恢复早于首次失败且同批次提交、新操作错误被覆盖或清除，以及恢复后的真实失败与成功重试。修复后相关 9 个测试文件共 121 项通过。

- `test/network-resource-regression.test.ts`：首次读取挂起与失败先复现，再覆盖修复；包含中途断开、首字节前取消、部分响应失败、HEAD、空文件与缓存头。
- `test/log-stats-reader.test.ts`：真实 SQLite/worker、主线程响应、并发写入与删除的一致快照、队列饱和、取消、关闭、SQL/启动失败、执行期限与索引计划。
- `test/server-log-analytics.scenarios.ts`：完整及 usage HTTP 合同、参数错误、过载和普通错误区别、客户端断开以及等待统计时的健康接口。
- `test/ui-stats-lifecycle.test.tsx`：切页快照、到期刷新、强刷、失败保留、隐藏取消、旧响应保护以及两侧 bootstrap 独立提交；相关原有 UI 回归同时执行。

10 万行纯合成数据采样（同机、Node 22）：保留范围中位数 `3.861 → 0.003ms`，recent compact `0.110 → 0.027ms`；同一数据的完整 overview 为 `1748–1898ms`，usage 为 `716–792ms`，请求数与用量相同。统计执行期间主线程 10ms 定时器最大间隔 `11.724ms`。这些是合成采样，不是生产 P95，也不表示首次统计降至毫秒级。

回归修复后的完整门禁在隔离目录按 `npm run check` 原顺序通过：161 个测试文件、2518 项通过、1 项因缺少既有本地抓包 fixture 跳过；严格类型检查与生产构建通过，工作区源码与验收副本逐文件一致。

修复后复审未发现新的功能回归，覆盖配置/草稿/保存 revision、错误恢复、统计与 CSV 口径、日志下钻、清理及关闭流程；代理与加密块恢复代码未改动。60 秒快照复用、隐藏页暂停刷新、统计过载/期限、静态首读期限以及维护等待读事务是明确的调度与失败行为变化，不能概括为仅增加索引。复审基于源码和隔离测试，不代表生产数据验证。

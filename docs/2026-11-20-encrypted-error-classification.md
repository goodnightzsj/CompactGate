# 加密错误变体：语义与诊断装饰分离

## 问题与目标

日志 #317164 的 `code: null` 错误在明确解密失败语句后带有 `[hub-] [trace_id=…]`。旧分类器将完整文案和固定诊断尾部绑定，额外标签使分类及 item 定位同时失败，恢复未触发。

修复所有原生 Responses 调用共用的 `src/server/provider-state-errors.ts`。不枚举 hub 品牌，不将任意 HTTP 400、任意含 encrypted 的文案或任意嵌套 JSON 归为可恢复故障。

## 方案

稳定错误码仍是首要依据。缺少明确码时，仍要求 HTTP 400、既有 `invalid_request_error` 信封及完整的肯定解密/校验失败语句。

在检测副本上归一化空白，通过同一个 `messageTarget` 剥离受限装饰、匹配失败语义并提取目标。明确码分支也复用该定位结果，防止新增后缀只修复分类却遗漏 item ID。

装饰按语法而非供应商品牌识别：

- 边缘方括号标签：未知的 ASCII 标识符，可带 `:` 或 `=` 键值，例如 `[hub-]`、`[region=ap-south-9]`、`[trace-id: synthetic/segment]`。
- 边缘圆括号键值：一到两个标识符词，值保持既有 request ID 的字母、数字、下划线和连字符限制，例如 `(request id: request_123-X)`、`(Node ID: east-1)`。
- 开头的既有网关错误前缀可与标签交错、多层组合；诊断标签可位于两端，request/trace 顺序可变化。
- 语义支持大小写、换行/空白、等价否定谓语、`Reason`/`Cause` 及可选句末点号或叹号；问句、肯定成功、引用、额外解释和不完整失败语句仍不识别。

未知诊断名称遵守相同语法即可被兼容，无须再按 host 添加正则分支。未知失败措辞或错误包装没有确定合同则保留真实失败，不能宣称任意未来自然语言均可自动恢复。

## 恢复与数据边界

- 文案上限仍为 65536 字符，最多剥离 8 个前缀/标签；标签的每段标识符至多 64 字符、值至多 128 字符。
- 归一化后的重复诊断键拒绝，包括 `trace_id`/`trace-id`、`request_id`/`Request ID`；畸形、嵌套、空值或超限装饰不成为文案证据。
- 对整段剩余语义匹配，不做词袋、自由子串扫描或递归解包；Go 数字 code 的既有单层解包合同保持。
- 保留完整 item ID 或完整密文 SHA256；缩略密文不作为身份。检测不改变响应字节、trace、错误码或类型。
- 不修改资源冲突判据、四个不同正文的总预算、固定目标/凭据、SSE 64 KiB/1 秒守卫、输出/取消后不重放、缓存及检查点。
- 标签不授权删除上下文；只按既有真实拒绝、定位、检查点/摘要优先和有损恢复限制执行。无材料且不符合限制时保留失败。

OpenAI 官方将 compaction 定义为携带历史状态的不透明加密项；本地格式识别不是解密，不保证跨资源接纳或隐藏推理等价。[官方 compaction 文档](https://developers.openai.com/api/docs/guides/compaction)
